# Agent Note: 本地 MCP 接口驱动迁移与回迁

Status: implemented

## Problem

Issue #3 要求提供 MCP 服务供 AI 读取和调用，能够创建和执行迁移与回迁，效果与 App 一致，结果必须能在 App 中操作。AppPorts 现有迁移入口都在 SwiftUI 视图状态里：外部进程既读不到应用列表与迁移日志，也无法把迁移交给任务中心，所以只做一条 CLI 或直接复制文件都会产生第二套迁移语义。

## Decision

App 内新增一条仅监听 `127.0.0.1` 的 Streamable HTTP MCP 端点，默认关闭、需在设置中显式开启，并为每个安装生成 Bearer 令牌；同时校验 `Origin`，只接受回环来源。一次 POST 承载一条 JSON-RPC 消息，响应固定为 `application/json`，不开启 SSE，也不向客户端发请求。协议版本按 `2025-06-18`、`2025-03-26`、`2024-11-05` 协商。

工具面固定在七个：`appports_status`、`appports_list_apps`、`appports_list_transfers`、`appports_migrate_app`、`appports_restore_app`、`appports_task`、`appports_cancel_task`。

写操作不自行复制文件，而是向 `MigrationTaskCenter` 提交任务，与 UI 共用操作锁、journals、签名/搜索/Dock 收尾和任务中心展示；任务完成后按与 UI 相同的方式写入 `AppListTransfer` 与 `AppSearchRecordStore`，再由记录变化通知驱动主界面重扫。因此 AI 发起的迁移在 App 里可见、可暂停、可取消、可在失败后重试，退出 App 后任务与记录仍在。

预检与 UI 同源：新增 `AppMigrationPolicy` 统一“不可迁移”的原因，`ContentView.migrationSkipReason` 改为委派它；自更新应用（uchg 保护）必须带 `lock_external=true` 才执行；目标卷与应用同卷、目标已存在同名应用、存在未完成迁移记录、前台操作进行中，一律拒绝并给出下一步提示。回迁接受外部路径或本地入口，默认还原到 `localDestinationForRestore` 计算出的原入口位置，可用 `local_destination` 覆盖；本地存在同名真实应用时拒绝。

设置页新增“AI 接入（MCP）”区：开关、endpoint、掩码令牌、复制客户端配置、重新生成令牌。端点随 App 启动按设置恢复，App 退出即停止；XCTest 宿主不启动。

## Wire and security details

- 方法：`initialize`、`ping`、`tools/list`、`tools/call`，通知按 202 应答；未知方法 `-32601`，参数/未知工具 `-32602`，解析失败 `-32600`/`-32700`；工具内的业务失败以 `isError: true` 的文本结果返回，会话继续。
- 请求体上限 4 MB、请求头上限 32 KB；每个连接只处理一条请求，`Connection: close`。
- 令牌用 `SecRandomCopyBytes` 生成并保存在应用自己的偏好域，比较用常量时间；DNS rebinding 由 `Origin` 白名单挡住，非回环 `Origin` 返回 403，缺令牌 401。
- 工具执行留在主 actor；`MCPToolService.Environment` 把扫描、迁移/回迁步骤、卷判断、策略和任务中心全部做成注入点，测试不触碰真实应用与外置盘。

## Alternatives considered

- 独立 CLI / 独立进程跑迁移：AI 客户端可直接用 stdio 启动，App 不必常驻。但迁移必须与运行中的 App 共用操作锁与任务中心；两个进程写同一 journals 会绕过界面的忙碌状态，任务也不会出现在任务中心。放弃。
- App 二进制加 `--mcp` stdio 模式：没有 HTTP 面，最省事。但 App 是 GUI 进程，同时只能有一个实例持有迁移状态；另起 headless 进程要重做写入资格与界面刷新，任务同样进不了任务中心。放弃。
- MCP 直接调用 `AppMigrationService` 复制：代码最短。但会绕过任务中心、并发上限、暂停/取消与界面记录，与“和 App 执行功能一致”冲突。改为在任务内部执行。
- 允许 MCP 覆盖外置盘同名应用：省一次人工确认。但版本比较、降级与更新保护都需要人判断，v1 明确拒绝并指向 App 处理。
- 端点常开、只靠令牌：少一个开关。但同用户进程都能读偏好域里的令牌，误用面更大；默认关闭更符合仓库现有的显式确认风格。

## Consequences

端点只在 App 运行时存在，AI 不能在 App 退出后继续迁移；这换来的是任务、锁与记录始终由同一个进程拥有。MCP 不新增任何文件系统权限，写操作仍走服务层校验。今后任何新的迁移入口都应复用 `AppMigrationPolicy` 与任务中心，否则会再次出现两套行为。令牌保存在偏好域，同用户进程仍可读取；端点默认关闭、仅回环、带 Origin 校验，是这一取舍下的边界。
